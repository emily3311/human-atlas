## 1. 产品定位

产品名称：经纬 · 人体图谱。

主要使用场景：

1. 在三维人体上认识解剖结构，并与经穴文字定位结合学习。
2. 通过搜索、经络/部位筛选查找穴位，阅读中文名称与已具备的知识资料。
3. 用正面问题、点击翻面答案的记忆卡复习。
4. 做取穴自测、管理自己的复习记录和课程。
5. 使用中医执业医师单选题练习、搜索题目、回顾错题。

设计目标：让“看清结构”和“读懂题目”比装饰、口号和卡片数量更重要。

不是临床处方工具，也不是提供个体针灸/艾灸操作指导的系统。

## 3. 当前设计风格：真实代码中的基线

当前总体是“米白底、棕色字、宋体标题、橙色主操作”，局部用了暖灰渐变和浅桃色工具条。现状中辅助文字较淡、字号偏小，浮动控件较多，长时间阅读的清晰度还有改进空间。

以下是当前值，不是必须原样保留的最终规范：

| 用途 | 当前色值/值 | 改版方向 |
| --- | --- | --- |
| 页面底色 | `#F8F4ED` | 保留干净的米白感，可向暖灰靠近 |
| 主文字 | `#392B23` | 深棕，保持足够对比度 |
| 次级文字 | `#A38570` | 当前较淡，正文性信息应加深 |
| 强调色 | `#C26832` | 少量用于选中、进度或重要操作 |
| 主按钮 | `#A64F23` | 橙棕实色，可统一调整 |
| 分隔线 | `#ECE2DA` | 低对比细线，只分区不抢眼 |
| 顶栏 | `#FCFAF6` | 轻、薄，减少装饰占高 |
| 模型背景 | `#F8F5EF` 至 `#EEE9E2` 渐变 | 可改成均匀暖灰，不影响模型识别 |
| 中文正文 | 系统无衬线：PingFang SC、Microsoft YaHei等 | 正文易读、字体加载失败有回退 |
| 标题 | Noto Serif SC、Songti SC、serif | 宋体只点到为止，不用于密集题干和按钮 |

代码基线正文13px，部分标签10—12px。建议设计稿正文提高到14—16px，题干16—18px，并让字号和间距随屏幕适配；这些是设计建议，不是已经实现的事实。

建议采用4/8px间距体系、克制阴影、约8—12px圆角。不要让每一行、每一段都变成独立大卡片。

## 4. 必须保留的交互

### 4.1 三维解剖：连续散开，而非二态切换

- 原参考项目：[Human Atlas](https://github.com/ashemag/human-atlas)，[原版演示](https://human-atlas-seven.vercel.app/)。
- 滑块从完整人体连续过渡到逐结构散开的排列，中间任意位置都可停留。
- 滑块要容易抓取、可键盘操作、有当前值，但外壳不应像大卡片遮住模型。
- 保留结构点选、中文名称、单独查看、复位、相机控制。
- 散开状态默认清爽；左侧目录和右侧详情均可独立显示/隐藏，隐藏后让出空间。
- 鼠标悬停名称提示简短；较长说明在用户明确打开详情后才出现。
- 名称提示、已选结构条、滑块和相机工具不能叠在一起。
- 散开之后不能因为大量卡片而把模型压到狭窄区域。

### 4.2 经穴图谱：目录/模型/详情明确分工

- 左侧：搜索、筛选摘要、数量、可滚动条目；支持调整宽度和放大阅读。
- 中间：人体主视图；图层与视角工具条位置稳定，不遮挡正在观察的区域。
- 右侧：穴位名称、编号、归经、定位、学习操作与已具备的资料。
- 不把所有标签、按钮、说明在同一视觉层级平铺。
- 不为视觉“全面”增加没有校准的穴位标记；对无三维位置的条目继续提供文字阅读路径。
- 不重新显示此前已移除的裸露体表外观。

### 4.3 记忆卡：题目与答案有明确状态

- 正面是一道清晰的问题；点击/键盘翻面才看答案。
- 翻面动作轻、快，并尊重减少动态效果设置。
- “不会 / 模糊 / 记住了”的按钮有稳定位置和明确作用。
- 不能为了美观同时露出背面答案，或用纯装饰卡片替换已有复习调度。

### 4.4 执医题库：独立宽版阅读空间

建议布局关系：

```text
全局导航
────────────────────────────────────────────
执医题库                         关于题库
搜索题干或选项
全部题目 / 错题回顾        顺序 / 随机
────────────────────────────────────────────
第 n / 当前集合总数题                    单选
题干：支持长病例、换行、合理行宽
A  选项
B  选项
C  选项
D  选项
E  选项
提交答案
［提交后］答案、作答反馈、暂无解析
上一题                               下一题
```

- 示意图只说明层级，不限定最终排版。
- 题目页面没有人体画布和穴位目录占位。
- 未提交前不显示答案；提交按钮在未选择时禁用。
- 用文字/图标区分“所选选项”和“答案”，不能只靠颜色。
- 错题答对后保留当前反馈，不要立刻让整张题消失。
- 来源和许可证在关于说明中；不贴在每道题旁边。
- 没有解析就显示“暂无解析”，不能用自动生成内容冒充标准解析。
- 顺序/随机、搜索、错题、空状态、加载失败/重试、清除记录/取消均需设计。

## 5. 响应式与可访问性

至少给出1440px桌面、1024px较窄桌面/平板、390px手机三个版本。

- 桌面端模型主导空间；阅读页有适当最大行宽，不让文字横跨整屏。
- 1024px时不能硬塞固定宽度三栏，让模型只剩一条缝。
- 手机端目录/详情用抽屉或分屏切换，不同时铺开全部面板；导航可横向滚动或合理收纳，入口可发现。
- 触控目标建议至少44×44px，滑块拇指及拖拽把手要可操作。
- 焦点可见；抽屉/弹窗支持关闭和键盘退出，关闭后焦点返回触发控件。
- 长题干和长中文选项不截断；不能把关键操作放到不可达的屏幕外。
- 正文对比度建议达到WCAG AA要求；请实际检查色对比，不仅凭观感。
- 图标配可理解的文字或无障碍名称，少用孤立含义不明的符号。
- 颜色偏好明确：不要绿色作为主色或大面积成功色，可用深棕/橙色配合文字图标反馈。

## 6. 希望 Claude Design 交付什么

1. **视觉基础**：色板、字号层级、字重、行高、间距、圆角、阴影、图标规范。
2. **关键页面**：完整人体、连续散开中间态与末态、详情展开/收起、经穴文字详情、记忆卡正反面、题库未答/已答。
3. **交互状态**：hover、focus、disabled、loading、error、empty、selected、submitted；错题页与清除确认。
4. **响应式稿**：1440、1024、390px，标明哪些区域滚动、哪些保持固定。
5. **工程交接**：组件变化表和CSS变量，注明哪些仅改样式、哪些涉及布局结构；优先提供可套用的React/CSS片段或补丁。
6. **保持不变清单**：数据结构、数据数量绑定、模型加载/渲染、散开计算、学习记录和答案逻辑。

不需要交付新的营销首页、登录付费流程、医生社交系统、AI诊断聊天框或自动出题系统。
